# Інструментарій і робочий процес — Guidelines

> Рівень **Handbook**: пояснює поняття й показує, як застосовувати рішення зі
> [Standards](../Standards/index-uk.md). Правила цього рівня діють у code review, але стратегічний
> контракт — там. Реалізації — у [Reference-Recipes](../Reference-Recipes/).

## Лінт і мертвий код

Деталізація `FE-QC-01`.

| ID | Правило | Контроль |
| --- | --- | --- |
| FE-QC-01 | Лінтинг у CI **MUST** використовувати type-checked конфіг `typescript-eslint` плюс плагіни `react`, `react-hooks` і `jsx-a11y`. | `eslint.config.js` † |
| FE-REACT-06 | Усі проєкти **MUST** підключати пресет `eslint-plugin-react-hooks` `recommended-latest` — він уже несе діагностику React Compiler. | `eslint.config.js` |
| FE-QC-02 | Prettier **MUST** бути єдиним форматером; стилістичні правила ESLint залишаються вимкненими. | CI-джоба `format` |
| FE-QC-03 | Кожен коментар `eslint-disable` **MUST** вказувати конкретну причину поруч. | `eslint-plugin-eslint-comments` † |
| FE-QC-04 | Джоба лінту **MUST** запускатися з `--max-warnings=0`. | CI † |
| FE-QC-05 | Кожен публікований пакет **MUST** мати в CI перевірку мертвого коду (knip) і циклічних залежностей. | CI (сьогодні: лише `ui`) |
| FE-QC-06 | Артефакти білду (`dist`, `.next`, `storybook-static`, `coverage`) **MUST** бути виключені зі скоупу лінту, форматування та knip. | ignore-файли |

## Залежності

Деталізація `FE-DEP-01`.

| ID | Правило | Контроль |
| --- | --- | --- |
| FE-DEP-02 | CI **MUST** встановлювати залежності із закоміченого замороженого lockfile. | `--frozen-lockfile` |
| FE-DEP-04 | Install / build скрипти залежностей **MUST** бути явно в allowlist, ніколи не виконуватись без перегляду. | `onlyBuiltDependencies` |
| FE-DEP-05 | Версії прямих залежностей **MUST** бути запіненими або вузько обмеженими — без wildcard і плаваючих діапазонів. | review |

## Git

| ID | Правило | Контроль |
| --- | --- | --- |
| FE-WF-01 | Гілки **MUST** відгалужуватися від `main`, бути короткоживучими й мати вигляд `<type>/<ticket>-<slug>`. | review |
| FE-WF-04 | Pre-commit **MUST** завершуватися за ≤ 10 с, а pre-push за ≤ 60 с; усе повільніше живе тільки в CI. | домовленість |
| FE-WF-05 | `--no-verify` **MUST NOT** використовуватися поза задокументованою аварійною ситуацією, підтвердженою рев'ювером. | процес |
| FE-STACK-02 | Мажорні оновлення core-бібліотек **MUST** виноситись в окремий PR, ніколи не всередині фічі. | review |

## Конфігурація

Деталізація `FE-WF-08` і `FE-NEXT-11`.

| ID | Правило | Контроль |
| --- | --- | --- |
| FE-NEXT-11 | Серверна конфігурація **MUST** читатися з `process.env` під час запиту, а не вшиватися в білд. | review |
| FE-WF-07 | Справжні `.env*` файли **MUST NOT** комітитись; трекається лише `.env.example`. | `.gitignore` |
| FE-WF-08 | Старт застосунку **MUST** валідувати обов'язкові змінні середовища за схемою і падати одразу. | review † |

## CI та деплой

Деталізація `FE-WF-03` — які саме перевірки мають бути зеленими, і що відбувається після мерджу.

| ID | Правило | Контроль |
| --- | --- | --- |
| FE-WF-06 | CI на PR **MUST** проходити frozen install, lint, format, typecheck, unit-, interaction- і visual-тести та білд до мерджу. | `quality.yml` |
| FE-WF-09 | Продакшн-деплої **MUST** виконувати один незмінний артефакт, з гейтом на зелений CI і задокументованим відкатом. | pipeline † |
