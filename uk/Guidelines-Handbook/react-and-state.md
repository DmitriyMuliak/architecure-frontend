# React, стан і форми — Guidelines

> Рівень **Handbook**: пояснює поняття й показує, як застосовувати рішення зі
> [Standards](../Standards/index-uk.md). Правила цього рівня діють у code review, але стратегічний
> контракт — там. Реалізації — у [Reference-Recipes](../Reference-Recipes/).

## Компоненти й хуки

| ID | Правило | Контроль |
| --- | --- | --- |
| FE-REACT-01 | `useEffect` **MUST NOT** обчислювати похідний стан, обробляти події користувача чи тягнути дані, доступні на етапі рендеру. | `eslint-plugin-react-hooks` (частково) + review |
| FE-REACT-02 | `useMemo`, `useCallback` і `memo` **MUST NOT** додаватися без підтвердженої профайлером реальної регресії. | review |
| FE-REACT-03 | Стейтова логіка, спільна для двох і більше компонентів, **MUST** виноситись у хук із префіксом `use`. | review |
| FE-REACT-04 | Компоненти **SHOULD** віддавати слоти для композиції замість накопичення boolean-прапорців варіантів. | review |
| FE-REACT-05 | `[R19]` Компоненти **MUST** приймати `ref` як звичайний prop замість `forwardRef`. | `eslint » no-restricted-imports` † |
| FE-REACT-07 | Нові проєкти **MUST** вмикати React Compiler. | `next.config.ts` |
| FE-REACT-08 | Окремий `eslint-plugin-react-compiler` **MUST NOT** використовуватися — діагностика вбудована в `eslint-plugin-react-hooks`. | review |

## Транспорт даних

Деталізація `FE-DATA-07` і `FE-DATA-08` — третя нога тріади й окремий випадок, який регулярно
намагаються провести через Server Action.

| ID | Правило | Контроль |
| --- | --- | --- |
| FE-DATA-09 | Server Components **MUST** читати з джерела даних напряму, ніколи через власні Route Handlers цього застосунку. | review |
| FE-DATA-14 | Завантаження важких файлів **MUST** іти напряму на бекенд або через стрімінговий Route Handler — ніколи через Server Action, який буферизує все тіло в пам'ять. | review |

## Таксономія стану

Деталізація `FE-DATA-11`.

| ID | Правило | Контроль |
| --- | --- | --- |
| FE-DATA-11 | Кросс-роутовий клієнтський стан **MUST** жити в Zustand-подібному сторі; Context — лише для низькочастотного інжекту (тема, локаль, сесія). | review |
| FE-DATA-01 | Дані, доступні на момент запиту, **MUST** тягнутися в Server Components, а не в клієнтському ефекті чи запиті. | review |
| FE-DATA-02 | Стан компонента **MUST NOT** дублювати значення, яке виводиться з props, URL або кешу. | review |
| FE-DATA-03 | Стан UI, яким можна поділитися посиланням (фільтри, таби, пагінація), **SHOULD** жити в URL search params. | review |
| FE-DATA-04 | React Context **MUST NOT** використовуватися для високочастотних оновлень або як кеш серверного стану. | review |

## Форми

| ID | Правило | Контроль |
| --- | --- | --- |
| FE-DATA-12 | Форми **MUST** будуватися на React Hook Form + Zod; прості форми на server actions **MAY** використовувати `useActionState`. | review |
| FE-DATA-13 | Нові проєкти **MUST** використовувати `zod/mini`; наявні мігрують на нього поступово. | review |
| FE-DATA-05 | Форма **MUST** валідуватися однією схемою, спільною для клієнта і серверної межі. | review |
| FE-DATA-06 | Обробники сабміту **MUST** віддавати pending-стан, а помилки полів **MUST** рендеритись біля свого поля. | review |
